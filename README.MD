# «Сто к одному» — табло и пульт оператора

Приложение для проведения «Сто к одному»: зрительские табло основной и большой игры, операторские пульты, счёт, промахи, таймер и поддержка кнопок Buzz!.

Windows Forms, VB.NET, .NET Framework 4.8. Правила работы с пультами описаны в [памятке оператора](OPERATOR_GUIDE.MD).

## Открытие в Visual Studio

Откройте `StoKOdnomuControl.sln` в Visual Studio 2022 с компонентом «Разработка классических приложений .NET» и .NET Framework 4.8 Developer Pack. Стартовый проект — **StoKOdnomuControl**. `RegressionTests` — консольные проверки, запускать его вместо приложения не нужно.

Восстановите пакеты NuGet через контекстное меню решения → «Восстановить пакеты NuGet». При установленном NuGet CLI можно выполнить `nuget restore StoKOdnomuControl.sln`. Затем выберите Debug/Release и соберите решение.

Пульты `Form1` и `BigGameControl` используют программную компоновку: `BuildUi` вызывает функции отдельных панелей, общие элементы находятся в `OperatorUi.vb`. Подписи и размещение операторских элементов редактируются в этих методах. Зрительские формы `Tablo`, `BigGameTablo`, окно «О программе» и пасхалка используют WinForms Designer.

## Сборка и проверки из PowerShell

Из корня проекта:

```powershell
./scripts/build.ps1
./scripts/verify.ps1
./scripts/verify.ps1 -Ui
./scripts/build.ps1 -Package
```

Скрипты находят MSBuild через `vswhere` установленной Visual Studio; интернет для сборки после восстановления пакетов не нужен. `-Ui` дополнительно проверяет команды кнопок и сохраняет снимки окон и диалога закрытия в отдельной временной папке. Звук в этом прогоне выключен; отчёт содержит путь к снимкам. Тесты используют свои сохранения, не затрагивая сохранённый матч оператора.

Для проверки автосохранения тестов требуются права на создание и замену файлов во временном каталоге Windows, включая `File.Replace`.

`-Package` создаёт новый каталог `artifacts/release-<дата-время>/app` без старых DLL и результатов предыдущих сборок. Переносите **весь `app`**, включая DLL, `Fonts`, четыре TXT-базы и памятку. Запускайте `StoKOdnomuControl.exe`. Windows Media Player для запуска не требуется.

## Устройство кода

| Файл | Назначение |
|---|---|
| `GameState.vb` | Типизированное состояние, правила начисления и переходов |
| `GameSession.vb` | Проверка команды до применения, общая история 100 отмен, сохранение и журнал |
| `QuestionBankReader.vb` | Проверка существующего формата TXT без изменения текущей базы при ошибке |
| `Form1.vb`, `BigGameControl.vb` | Действия оператора, черновики полей, обновление интерфейса |
| `Tablo.vb`, `BigGameTablo.vb` | Отображение снимка состояния без начислений и звуков |
| `BoardLayout.vb` | Масштабирование фона и подписей, комплектные шрифты, полноэкранный режим |
| `SplashEditor.vb`, `SplashOverlay.vb` | Черновики двухстрочных заставок, пресеты и отдельный слой зрительского табло |
| `AudioService.vb` | Кэш декодированных WAV, независимые каналы эффектов/Buzz!/отсчёта |
| `Countdown.vb` | Отсчёт через Stopwatch и управление только его звуковым треком |
| `BuzzManager.vb` | Типизированные состояния приёмника, асинхронное подключение, допуск и ничьи |
| `BuzzReceiver.vb` | Контракт приёмника и Windows HID: чтение кнопок, лампы, владение дескриптором |

`Option Strict On` действует для всего проекта. Для звука используются NAudio Core/WinMM и необходимые зависимости; Windows Media Player и COM-компоненты не используются.

## Ресурсы и данные

Изображения и звуки перечислены в `My Project/Resources.resx`: оформление 2026 года, `bing`, пять `ff_reveal` и ресурсы пасхалки. Исходные медиа хранятся отдельно от комплекта запуска.

`Новый дизигн` — исходники и варианты оформления, `Новые звуки` — исторические звуки/фонограммы; пять `ff_reveal` оттуда ещё используются. Корневой XCF и PNG — художественные исходники. Для запуска не копируйте всю рабочую папку: используйте комплект `-Package`.

Шрифты JetBrains Mono Regular/Bold и их OFL-лицензия копируются в `Fonts`. Табло загружает их как частные GDI+ шрифты; ставить все 18 TTF в Windows не нужно. При отсутствии файлов используется системный моноширинный шрифт, поэтому для сохранения оформления переносите комплект целиком.

Игра и последние 100 отмен сохраняются в `%LOCALAPPDATA%/StoKOdnomuControl/game.xml`, предыдущий снимок — `game.xml.bak`, журнал — `actions.log`. Запущен может быть один экземпляр приложения. Для изолированных проверок каталог переопределяется переменной `STOKODNOMU_DATA_DIR`. В сохранение входят оба текущих табло, заставка основного экрана и история отмены, но не библиотека будущих раундов и не незавершённый отсчёт. Формат сохранения — 2; файлы формата 1, включая историю, преобразуются при восстановлении. Неподдерживаемые версии отклоняются.

## Оборудование

Поддерживается приёмник с VID `054C`, PID `1000`. Кнопки читаются с того же HID-устройства, которым управляются лампы. Формат кнопок разбирается Windows HID parser по дескриптору; номера красных кнопок — 1, 6, 11, 16. Сопоставление соответствует [исходнику драйвера Sony в Linux](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-sony.c), контракт парсера — [Microsoft HidP_GetUsages](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidpi/nf-hidpi-hidp_getusages).

Реальные USB-приёмник, лампы, аудиовыход и проектор должны пройти репетицию. Автоматические проверки проверяют правила арбитража, состояния реального менеджера на тестовом транспорте и доступность кнопок пульта при потере связи. Они не подтверждают работу конкретного USB-приёмника, его ламп или задержки радиоканала.

Точные ссылки на использованные фрагменты StackOverflow в исходниках отсутствовали: они не выдумывались. Лицензии NuGet-пакетов и OFL шрифтов сохраняйте при поставке.
